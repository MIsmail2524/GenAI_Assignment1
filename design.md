    # Google Stitch Design Brief

    ## Purpose

    Create and document the original interface design for the Multi-Corruption
    Restoration Suite in Google Stitch. This is a design brief, not a claim that
    the existing React interface was generated by Stitch. Save the actual Stitch
    screenshots, share link, and generation history as evidence after completing
    the steps below.

    ## Prompt To Paste Into Google Stitch

    ```text
    Design a polished, usable web application called "Restoration Suite" for
    testing four image restoration and face-to-sketch ONNX models. This is an
    operational ML tool used repeatedly by students and evaluators, not a landing
    page. Open directly into the working application with Task 1 selected.

    Create one coherent responsive desktop-and-mobile interface with four clearly
    named workspaces:
    1. Universal Restoration
    2. Hard-Routed Restoration
    3. Soft Mixture-of-Experts Restoration
    4. Face-to-Sketch Generator

    Visual direction: a precise image-lab instrument panel, calm and technical,
    with a bright neutral canvas, near-black typography, fine cool-gray dividers,
    and a restrained signal-coral accent for active controls and warnings. Use
    distinct but harmonious colors for the four routing classes. Use a purposeful
    humanist sans-serif for interface text and a compact monospace face for model
    metadata, probabilities, and inference timings. Avoid purple, generic SaaS
    marketing layouts, oversized hero sections, decorative gradients, nested
    cards, and unnecessary explanatory copy. Favor clear hierarchy, compact
    controls, generous image preview space, and accessible contrast.

    Use a persistent application header with the product name, a small API/model
    status indicator, and four compact workspace tabs or navigation links. Make
    the active workspace immediately obvious. Each workspace should be a real
    working screen with empty, loading, error, and completed-result states.

    Universal Restoration screen:
    - Provide an image upload/drop area and a preview of the selected image.
    - Provide a corruption selector with None, Clean, Salt-and-Pepper, Gaussian
    Blur, and Occlusion options. Show Low, Medium, and High severity only when
    an artificial corruption is selected.
    - Make the original input and restored output the primary visual comparison.
    - Show selected corruption settings, inference time, and a clear notice when a
    clean image was passed through unchanged.

    Hard-Routed Restoration screen:
    - Provide image upload and optional corruption/severity controls.
    - Show input and restored output side by side.
    - Show the predicted class, selected expert, inference time, and all four
    classifier probabilities in a compact, readable probability visualization.
    - Make the clean identity bypass explicit.

    Soft Mixture-of-Experts Restoration screen:
        - Provide image upload, input/output comparison, and runtime corruption
            controls with severity selection.
    - Show all four routing weights (clean identity, salt-and-pepper, blur,
    occlusion), the dominant expert, and inference time.
    - Use both a clear weight visualization and a concise contribution breakdown.
    - Indicate when the clean branch is dominant and the original is returned
    unchanged.

    Face-to-Sketch Generator screen:
    - Accept a photo upload and offer a webcam capture action.
    - Provide a three-option segmented style selector labeled Style 1, Style 2,
    and Style 3.
    - Show the original face and generated sketch side by side, with a clear
    download-result action and inference time.

        Add an Inference Run Log below the workspace with timestamp, workspace,
        input filename, settings or routing details, inference time, Export JSON,
        and Clear controls. Label this as inference history, not training or Optuna
        history.

    On narrow screens, stack image comparisons vertically, keep controls within
    the viewport, and make navigation usable without horizontal overflow. Use
    realistic but clearly sample-only image placeholders; do not invent model
    metrics, probabilities, or claims. Include one desktop screen for each
    workspace and one mobile layout demonstrating the responsive behavior.
    ```

    ## Google Stitch Workflow

    1. Open Google Stitch and create a new design named `Restoration Suite`.
    2. Paste the prompt above and generate the initial design.
    3. Generate or refine screens for all four workspaces and a narrow mobile
    layout. Keep the prompts and meaningful revisions in the Stitch project.
    4. Review the screens against the required controls and states in the brief.
    Correct missing or inaccurate controls before treating the design as final.
    5. Use Stitch's share/export options to preserve the design and its revision
    history. Do not recreate or edit screenshots to make them look like Stitch
    output.
    6. Save genuine screenshots and the share URL in the evidence section below.
    7. Compare the approved screens with the React implementation. Record any
    deliberate differences; Stitch designs are not automatically evidence that
    the implementation matches them.
